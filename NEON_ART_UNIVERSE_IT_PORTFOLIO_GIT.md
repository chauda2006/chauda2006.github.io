# NEON ART UNIVERSE — IT PORTFOLIO WEBSITE CONCEPT
> **Git-ready creative brief | Neon line art × Cyber-luxury × Digital painting**  
> **Palette:** Crimson Red 🔴 + Emerald Green 🟢 + Obsidian Black ⚫  
> **Tagline:** *Where Logic Meets Imagination.*

---

## 01. Vision — A Portfolio That Feels Like Another World

Build more than a conventional online CV. The website should feel like entering a high-end digital universe where code, engineering, and visual art coexist.

Imagine a dark cinematic space filled with hand-drawn neon contours, floating mechanical parts, glowing gears ⚙️, circuit-board pathways, technical sketches, emerald data streams, crimson energy rings, and delicate particles. Every element should feel intentional, polished, and smooth.

The design must balance:
1. **Visual impact:** memorable, expressive, artistic, futuristic.
2. **Professional credibility:** easy to navigate, fast to load, accessible, and focused on real IT skills and projects.

### Design keywords
- Neon line-art and glowing hand-drawn contours
- Cyber-luxury and cinematic darkness
- Digital painting and technical illustration
- Mechanical geometry and animated gears ⚙️
- Emerald data streams and crimson energy trails
- Glass panels, subtle depth, layered lighting
- Smooth scroll reveals and carefully choreographed motion
- Professional typography and strong information hierarchy

## 02. Art Direction — The Crimson/Emerald Universe

| Role | Color | HEX | Purpose |
|---|---|---|---|
| Main background | Obsidian Black ⚫ | `#07090B` | Deep, cinematic base |
| Secondary background | Graphite | `#11151A` | Panels and cards |
| Main red accent | Neon Crimson 🔴 | `#FF244F` | Identity, energy, important actions |
| Deep red | Dark Crimson | `#8C1735` | Shadows and gradients |
| Main green accent | Neon Emerald 🟢 | `#38FF91` | Data, active states, technical details |
| Deep green | Forest Emerald | `#087A4A` | Secondary glow and depth |
| Main text | Ice White | `#F4F6F8` | Headings and important content |
| Secondary text | Silver Gray | `#A3ABB5` | Descriptions and metadata |

### Color balance
- 70% dark surfaces
- 20% deep red/green accents
- 10% bright neon highlights

Use crimson and emerald as two contrasting forces flowing through the interface. Red can represent creative energy and personal identity; green can represent logic, systems, and data. Let them intersect in selected areas rather than making every element glow.

### Visual materials
- Fine glowing SVG strokes
- Sketch-like crosshatching and hand-drawn contours
- Circuit traces and technical blueprint grids
- Translucent glass panels with thin neon borders
- Metallic gear silhouettes and rotating mechanical rings
- Soft bloom, restrained blur, and layered shadows
- Abstract 3D forms that resemble a digital sculpture

**Avoid:** excessive glow, rainbow gradients, constant glitch effects, dense particles, and decoration that hides the content.

## 03. Hero — “ENTER THE UNIVERSE”

The first screen should create a strong visual impression while immediately explaining who the portfolio belongs to.

### Layout
- Minimal top navigation with line-art icons.
- Large personal name or signature on the left.
- Concise professional introduction and two clear calls to action.
- Custom visual on the right: an illuminated mechanical core, hand-drawn cybernetic mask, rotating gear constellation ⚙️, or technical-art sculpture.
- Fine red and green lines traveling through the background like energy paths.
- Small system labels such as `SYSTEM ONLINE` or `CREATIVE MODE: ACTIVE`.

### Suggested hero copy

**CHÂU TIẾN ĐẠT**  
`IT STUDENT · DEVELOPER · DIGITAL ART ENTHUSIAST`

> I build digital experiences where logic meets imagination.

Buttons:
- `EXPLORE PROJECTS`
- `CONNECT WITH ME`

Optional technical microcopy:
- `STATUS: ONLINE`
- `BUILDING: DIGITAL EXPERIENCES`
- `VERSION: PORTFOLIO 1.0`

Use system labels as visual decoration only; do not imply a real live status if it is not implemented.

### Hero animation sequence
1. The screen begins in near-black.
2. Thin SVG paths draw themselves across the background.
3. A few gears and rings appear through a soft light reveal.
4. The name and title fade in with subtle movement.
5. Crimson and emerald highlights travel through selected paths.
6. The main CTA receives a precise animated border on hover.

The animation should feel cinematic, not slow. Core content must remain visible and usable when animations are disabled.

## 04. Signature Motif — The Living Machine ⚙️

Use gears as a recognizable visual signature, not as random decoration.

### Gear concepts
- One large outlined gear behind the hero artwork, rotating very slowly.
- Small technical gears forming a constellation around the profile.
- A gear-and-circuit emblem used as the portfolio mark.
- Gear teeth transformed into hand-drawn strokes, mixing engineering with illustration.
- Tiny mechanical icons beside skill categories.
- A gear changing from crimson to emerald when a project card becomes active.

### Motion rules
- Rotate only a few gears at once.
- Use different rotation speeds and directions for depth.
- Avoid fast spinning; slow movement feels more premium.
- Pause or reduce decorative motion when the user prefers reduced motion.
- Keep gear layers behind text and interactive controls.

### Other possible motifs
- 🧠 Wireframe brain for problem-solving
- 💻 Hand-drawn terminal or code window
- 🧬 Interwoven red/green data strands
- 🔗 Connected nodes representing APIs and systems
- ✦ Particles resembling digital dust
- ◈ A glowing core symbolizing the personal universe

Emoji can be used in concept notes or selected micro-details, but the main visual identity should rely on custom SVG icons and line-art. This keeps the finished website polished rather than looking like a page filled with unrelated emoji.

## 08. Projects — “ARTIFACTS FROM MY LAB”

Projects are the strongest evidence of technical ability and should be the center of the portfolio.

### Project card structure
Each card should show:
- Project preview image or short demo
- Project title and concise description
- Technology stack
- Personal role and contributions
- One technical challenge and how it was approached
- Links to live demo, repository, or case study when available

### Potential projects

#### AURA BEATS — Online Music Platform
A music-listening website. Depending on features actually completed, showcase the interface, audio playback, VIP access control, listening history, and admin tools.

#### Student Event Management System
A student event management system. Highlight the implemented database structure, APIs, registration flow, file uploads, or containerization where applicable.

#### Other experiments
Include smaller projects only when they demonstrate a clear idea, useful implementation, or thoughtful design.

### Interaction design
- Cards rise slightly on hover.
- Preview images scale subtly within a clipped frame.
- A thin red-to-green line traces one card edge.
- Tags identify technologies without overwhelming the layout.
- Filters allow visitors to browse by category.
- A detailed project view explains the problem, approach, implementation, and result.

**Important:** Clearly distinguish individual contributions from team output. Do not claim features or technologies that were not actually implemented.

## 12. Motion Design — Premium, Smooth, Purposeful

| Element | Motion | Intensity |
|---|---|---|
| Hero line-art | SVG stroke reveal | Signature |
| Mechanical gears | Slow rotation | Subtle |
| Background particles | Slow drift | Very subtle |
| Section headings | Fade and short vertical reveal | Moderate |
| Project cards | Small lift and border highlight | Subtle |
| CTA buttons | Animated outline or light sweep | Moderate |
| Timeline | Sequential reveal | Moderate |
| Gallery | Smooth lightbox transition | Moderate |
| Page transitions | Short fade/slide | Subtle |

### Implementation principles
- Prefer CSS `transform` and `opacity` for common animations.
- Use SVG for sharp, scalable line-art.
- Use `IntersectionObserver` for scroll-triggered reveals.
- Use `requestAnimationFrame` only when continuous custom animation is necessary.
- Limit simultaneous particle effects and animated layers.
- Respect `prefers-reduced-motion`.
- Do not block scrolling or hide important content behind long animations.
- Test on low-powered phones and smaller screens.

Premium motion comes from timing, restraint, and consistency—not from animating every object.

## 13. Recommended Technology

### Core version
- **HTML5:** semantic structure
- **CSS3:** layout, responsive design, gradients, glow, glass panels, transitions
- **JavaScript:** menus, filters, lightbox, interaction, motion
- **SVG:** custom gears, circuit paths, icons, line-art

### Optional enhancements
- **GSAP:** complex animation timelines

Build a polished, responsive 2D experience first. Add one signature 3D or canvas-based feature only after the main site is fast, readable, and complete. A well-crafted SVG illustration can look more distinctive and load faster than an unnecessary 3D scene.

### Basic Git workflow

```bash
# 1. Create a project folder and enter it
mkdir neon-art-universe
cd neon-art-universe

# 2. Initialize Git
git init

# 3. Add your website files
git add .

# 4. Create the first commit
git commit -m "Initial commit: Neon Art Universe portfolio"

# 5. Set the main branch name
git branch -M main

# 6. Connect your GitHub repository
git remote add origin https://github.com/YOUR-USERNAME/neon-art-universe.git

# 7. Push the project
git push -u origin main
```

Replace `YOUR-USERNAME` with the actual GitHub username and create the repository on GitHub before pushing. If the repository already has a remote or commits, inspect its state before running these commands.

### GitHub Pages notes
- A static HTML/CSS/JavaScript portfolio can be hosted on GitHub Pages.
- Use relative asset paths such as `./assets/images/profile.webp` so the site works from a repository subpath.
- GitHub Pages does not execute PHP server-side code. If the portfolio requires PHP, a database, login, or a working contact backend, deploy those components to a compatible server or use an appropriate external service.
- Do not commit passwords, API keys, private credentials, or personal data.
- Confirm that the published site works from the repository's actual Pages URL.

## 15. Responsive Design and Accessibility

- Design for mobile, tablet, laptop, and large screens.
- Keep navigation usable with touch and keyboard.
- Provide visible `:focus-visible` states.
- Use semantic HTML landmarks and logical heading order.
- Add meaningful `alt` text to informative images.
- Maintain readable text contrast against dark surfaces.
- Never communicate status by color alone.
- Label form fields and show clear error/success states.
- Respect `prefers-reduced-motion`.
- Reduce decorative particles and parallax on mobile.
- Test with keyboard navigation and browser developer tools.
